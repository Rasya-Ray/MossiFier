1. APA ITU MOSSIFIER
--------------------
Perangkat IoT pemantau & penjaga kualitas udara berbasis lumut (moss) hidup.
Tiga bagian proyek:
  a) Perangkat ESP32 (esp32_upgrade.ino): baca sensor, POST ke Supabase.
  b) Machine learning (branch machine_learning): model multilabel klasifikasi
     kondisi lumut (Sehat/Sakit/Mati) dari gambar, diproses per tile/grid
     (moss_tiles.py, grid_core.py, train_multilabel.py, live_server.py).
  c) Website dashboard (branch Main-Dashboard): monitoring untuk user.
Repo: github.com/Rasya-Ray/MossiFier
Branch: Main-Dashboard (web), machine_learning, Dashboard, MODUL,
        machine-learning/dashboard, machine-learning/dashboard-oc.

5. ALUR DATA SENSOR
-------------------
ESP32 --POST--> Supabase REST /rest/v1/devices (kolom: device_id, status,
air_quality, co2_in, co2_out, humidity, brightness, fan_speed). Satu baris =
satu kiriman (riwayat), device_id TIDAK unik; id default gen_random_uuid().
Dashboard: use-realtime.ts ambil 20 baris terakhir + subscribe INSERT (Realtime).
Status tanaman = TEKS BEBAS dari perangkat (mis. "Sehat"), ditampilkan apa
adanya (tidak ada lagi kode 1/2/3). Satuan: co2 ppm, humidity %; kualitas
udara, kecerahan LED, kecepatan fan tidak punya satuan di kode.
User memilih device di sidebar (disimpan localStorage); tanpa device ->
empty state, bukan angka 0. Realtime butuh: alter publication supabase_realtime
add table devices + policy RLS select/insert anon (sudah di contract.ts).

6. CHATBOT AI
-------------
Tombol chat kanan bawah /dashboard -> popup chat (components/dashboard/chat-widget.tsx).
Alur: widget -> POST /api/chat {messages, deviceId} -> server cek sesi ->
ambil 20 baris sensor terakhir device itu dari Supabase (lib/chat/sensor-context.ts:
nilai terbaru, min/maks/rata-rata, tren, peringatan data lama) -> panggil
OpenRouter /chat/completions (stream) -> teruskan teks polos ke browser.
Persona + pengetahuan (Mossifier, CO2, kelembapan, cahaya, lumut) ada di
lib/chat/knowledge.ts — edit di sana untuk mengubah gaya jawab/menambah ilmu.
Env (server-only, di .env, tanpa NEXT_PUBLIC_):
  OPENROUTER_API_KEY   wajib
  OPENROUTER_MODEL     default google/gemini-3.5-flash-lite
  OPENROUTER_BASE_URL  default https://openrouter.ai/api/v1
Keamanan: wajib login, deviceId divalidasi regex, riwayat maks 12 pesan x 1000
karakter, rate limit 15 pesan/menit/user (in-memory), status dari perangkat
dibersihkan sebelum masuk prompt, detail error penyedia hanya di log server,
balasan dirender tanpa dangerouslySetInnerHTML.
Pesan error di UI: 401/402 dari penyedia -> "kunci/saldo"; lainnya -> "sibuk".
Detail sebenarnya ada di terminal: baris "[chat] OpenRouter <status> ...".

9. CATATAN / MASALAH YANG PERNAH MUNCUL
---------------------------------------
- Node di Windows bisa kena "Connect Timeout" ke host eksternal (IPv6 dulu).
  Sudah ditangani: dns.setDefaultResultOrder("ipv4first") di app/api/chat/route.ts.
- Baris lama di tabel devices dengan status "1"/"2"/"3" tampil sebagai angka mentah.
- Di cmd Windows, JSON di curl harus pakai kutip ganda ("), bukan kutip tunggal (').
- Warning console "scroll-behavior: smooth": tambahkan data-scroll-behavior="smooth"
  pada <html> di app/layout.tsx bila ingin menghilangkannya.
- Rate limit chat in-memory: tidak dibagi antar instance serverless.
